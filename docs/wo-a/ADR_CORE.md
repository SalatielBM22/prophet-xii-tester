# Progressive core extraction

Dependency direction is portable arithmetic / musical time → DSP → control adapter → platform. Keep fixed-capacity event types, oscillator mixing and scheduler arithmetic in a dependency-free no_std rlib. Current voice/filter/effect preparation uses std float intrinsics and delay memory allocated at construction. Keep it in prophet-dsp until per-target float parity and memory are measured. The first extraction shares source using a path module, as the RC1 analysis bridge does. This allows both the independent rlib and the RC1 locked workspace to build without concurrent changes to the shared root manifests. B can replace the path bridge with a normal dependency during integration; hosts should import the adapter's re-exports so Rust types are identical.

Compile for installed x86_64 and AArch64 targets. Only prepare/configure may allocate. The bounded process API borrows equal-length stereo slices, a sorted command slice and caller-owned ACK storage. Stable wire fields are independent of Rust layout. Only fixed-size scalar/array DSP is eligible for extraction before parity. No plugin SDK, device backend or serializer dependency enters the portable crate.
